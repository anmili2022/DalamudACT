1. 文件位置与命名

DalamudACT 会优先加载当前语言对应的时间轴文件。中文时间轴建议使用 .cn.txt 后缀。

类型示例说明
普通时间轴klythios.txt通用文件。
中文时间轴klythios.cn.txt中文客户端优先使用，推荐维护这个文件。
索引文件timeline-index.json用于把副本区域 ID 或区域名映射到时间轴文件。

开发环境内置时间轴目录通常是：

DalamudACT/Features/Timeline/Data

发布包中会包含：

Timeline/Data
如果你只是自己测试，可以在游戏内使用“强制加载时间轴”选择本地文件。文件头写了 # ZoneId: 1234 后，插件重载时可按当前区域自动恢复强制加载。

2. 基础语法

一行时间轴通常由“时间 + 显示文本 + 可选事件 + 可选注释”组成。

12.5 "技能名"
18.0 "大范围AOE" duration 5
24.0 "分摊" # 分摊
部分说明
12.5战斗时间，单位秒。
"技能名"显示在时间轴窗口里的文本，也可用于 TTS 技能名。
duration 5持续时间，可用于显示长条。
# 分摊中文机制提示。插件会把明确的中文提示作为机制/TTS 来源。

持续条 duration

duration 表示这条机制会持续多久，单位是秒。适合连续攻击、场地效果、阶段窗口或一组多连击。

3101.5 "跃动的大地 (弧线)" duration 3.7

这表示从 3101.5s 开始显示“跃动的大地 (弧线)”，持续 3.7s，也就是大约到 3105.2s 结束。

普通英文备注不要随便写在 # 后面。插件会尽量过滤工具元数据，但建议只把真正希望显示/播报的中文机制写成注释。

3. 同步事件

同步事件用于把插件的时间轴时间校准到真实战斗事件。推荐至少提供一个可靠的开场同步点。

InCombat：进入战斗同步

0.0 "--sync--" InCombat { inGameCombat: "1" } window 0,1

进入战斗时启动时间轴。适合强制加载后等待同步，不想点加载后直接从 0 秒跑。

StartsUsing：Boss 开始读条同步

8.2 "重击" StartsUsing { id: "8ABC", source: "Boss名字" } window 5,5

当指定 Boss 开始读条指定 action id 时同步。source 可写 Boss 名字或正则。

Ability：技能结算同步

12.5 "重击命中" Ability { id: "8ABD" } window 5,5

当技能结算事件到达时同步。适合没有读条或需要按伤害结算校准的机制。

SystemLogMessage：系统日志同步

30.0 "--sync--" SystemLogMessage { id: "7DC", param1: "123" } window 20,5

用于封锁倒计时等系统提示。param1 会按客户端当前语言解析地点名，不建议按中文/英文硬编码整句日志。

NpcYell：Boss 台词同步

45.0 "--sync--" NpcYell { text: "台词内容" } window 10,10

用于 Boss 台词、喊话、对话类同步。

MapEffect：地图特效同步

60.0 "--sync--" MapEffect { flags: "00020001", location: "^04" } window 10,10

用于部分场地变化、机关、封锁等 MapEffect 事件。通常需要从调试日志中抓取。

window 语义

window first,last 表示允许同步命中的时间窗口：

[时间点 - first, 时间点 + last]

例如：

100.0 "--sync--" Ability { id: "8ABC" } window 20,5

表示当前时间在 80.0 到 105.0 秒之间时，才允许这条同步命中。

不要把阶段标题写成大窗口同步点，例如 "--Phase 3--" StartsUsing { ... } window 500,500。阶段文字只适合做标记，真正的同步应放在更贴近实际事件的唯一技能上，否则中途加载或异常观察顺序时很容易回跳到旧阶段。

4. 机制提示与 TTS

时间轴显示和 TTS 由三个开关控制：

播报机制播报技能名播报应对方案

内容来源示例受哪个开关控制
机制提示# 分摊播报机制
技能名"重击"播报技能名
应对方案读条ID 8ABC 开减伤播报应对方案
Timer 文本10.0 "踩塔" Timer播报应对方案

推荐机制提示写短词：

18.0 "Boss技能" StartsUsing { id: "8ABC" } # 分摊
28.0 "Boss技能" StartsUsing { id: "8ABD" } # 钢铁
38.0 "Boss技能" StartsUsing { id: "8ABE" } # 月环

5. 添加应对方案

应对方案用于在真实事件发生时即时播报，不依赖时间轴提前窗口猜分支。

读条ID：Boss 开始读条时播

20.0 "分摊读条" StartsUsing { id: "8ABC", source: "Boss名字" } # 读条ID 8ABC 靠近分摊

当 Boss 开始读条 8ABC 时，立即播报“靠近分摊”。

结算ID：Ability 到达时播

25.0 "点名结算" Ability { id: "8ABD" } # 结算ID 8ABD 分散远离

当结算事件 8ABD 到达时，立即播报“分散远离”。

一行写多个应对方案

40.0 "二连机制" StartsUsing { id: ["8AC0", "8AC1"] } # 读条ID 8AC0 去左 读条ID 8AC1 去右

与技能名开关的关系

如果勾选“播报技能名”，应对方案播报格式类似：

分摊读条，靠近分摊

如果没有勾选“播报技能名”，只播应对方案：

靠近分摊
推荐：应对方案写玩家要做什么，例如“靠近分摊”“去左”“面向外”“开减伤”，不要只写机制学名。

6. 完整示例

# ZoneId: 1234

0.0 "--sync--" InCombat { inGameCombat: "1" } window 0,1

8.0 "开场AOE" StartsUsing { id: "8A00", source: "Boss名字" } window 5,5 # AOE
8.0 "开场AOE" # 读条ID 8A00 全体减伤

18.5 "分摊" StartsUsing { id: "8A01", source: "Boss名字" } window 6,6 # 分摊
18.5 "分摊" # 读条ID 8A01 靠近集合

30.0 "分散点名" Ability { id: "8A02" } window 8,8 # 分散
30.0 "分散点名" # 结算ID 8A02 分散远离

45.0 "--sync--" NpcYell { text: "Boss台词内容" } window 10,10

60.0 "踩塔" Timer # 踩塔

上面示例包含：

  • 文件头 # ZoneId，用于强制加载自动恢复。
  • InCombat 开场同步。
  • StartsUsing 和 Ability 同步。
  • 读条ID 和 结算ID 即时应对方案。
  • NpcYell 台词同步。
  • Timer 纯计时提醒。

7. 游戏内验证

  1. 打开 /dps settings。
  2. 进入时间轴设置，选择或强制加载时间轴文件。
  3. 打开时间轴 Debug 模式。
  4. 进入副本，观察时间轴是否显示“已加载”。
  5. 进入战斗，观察是否从 InCombat、读条、结算、系统日志或台词同步。
  6. 看时间轴窗口底部，例如 [20.35]当前运行第2行，确认对应源文件行号。
  7. 开启强化日志后，可在日志里查看同步命中与慢帧信息。

常见日志含义：

日志说明
加载时间轴文件已找到并解析对应文件。
InCombat 同步命中进入战斗同步成功。
StartsUsing 同步命中读条同步成功。
Ability 同步命中结算同步成功。
SystemLogMessage 匹配系统日志同步成功。
NpcYell 同步命中Boss 台词同步成功。

8. 提交前检查清单

  • 中文时间轴优先写 .cn.txt。
  • 文件头尽量写 # ZoneId: xxxx。
  • 至少有一个可靠同步点：InCombat、StartsUsing、Ability、SystemLogMessage 或 NpcYell。
  • window 不要过宽，避免旧机制误同步。
  • # 注释只写真正想显示/播报的机制提示。
  • 读条ID 用于开始读条即时播，结算ID 用于 Ability 到达时即时播。
  • 动态变量如 ${dir}、${first} 不要原样放进 TTS 文本，应改成明确中文或过滤掉。
  • 在游戏内强制加载测试，确认倒计时、同步、应对方案和 TTS 开关都符合预期。
