# DalamudACT {{VERSION}} 发布说明

- 目标版本：`{{VERSION}}`
- 本文件由 `.github/workflows/release.yml` 读取并写入 GitHub Release 正文。
- 发布前请确认 `{{VERSION}}` 已与 tag、项目版本和仓库 metadata 保持一致。

## 本次重点

### 紧急性能修复

- 本版本是针对用户反馈“绝妖星打的时候会卡到个位数帧率，卸掉插件就没事”的紧急性能版。
- 副本内自动刷新策略从低延迟降回标准间隔，避免统计和时间轴在高压战斗里默认高频刷新。
- 副本内默认跳过时间轴 ActionEffect / StartsUsing 重型同步路径，减少 Boss 多段技能、多人技能包和读条轮询带来的主线程压力。
- 时间轴加载后建立运行时索引，Ability、StartsUsing、响应 TTS、系统日志、喊话和场地特效同步不再依赖高频全表扫描。
- 时间轴可见条目刷新增加短缓存，降低时间轴窗口打开时的每帧排序、过滤和列表分配。
- 副本内战斗流水默认按轻量口径记录，只保留开战、结束、死亡、场地特效、头顶标记和连线等关键事件，避免高频伤害、治疗和状态流水放大卡顿。

### 热路径减负

- 队友技能监控悬浮窗不再每帧重建成员与技能显示列表，改为复用缓存状态并动态计算倒计时。
- 状态监控会缓存状态名称和图标，减少反复查询 Excel sheet 的开销。
- 强化日志关闭时，不再额外执行 ActionEffect、Framework、统计和 DoT 的性能分段计时，降低默认使用路径上的 Stopwatch 与临时列表分配。
- 副本内战斗对象轮询间隔上调，减少高压战斗中 Framework 帧的额外工作量。

### 稳定性补强

- 插件释放过程中，聊天、命令和 Hook 回调会提前返回，降低卸载或热重载时继续处理事件的风险。
- 状态监控悬浮窗默认禁用滚动条，减少窄窗口或折叠状态下的布局干扰。

## 已知注意事项

- 本次属于紧急性能版，优先解决副本内主线程卡顿风险；如果仍能复现个位数帧率，请优先确认是否打开了时间轴窗口、状态监控窗口和完整战斗流水。
- 若仍有卡顿，可临时开启高性能模式，或关闭时间轴、状态监控、战斗流水后再次进入同一副本对比。
- 需要继续定位时，请开启强化日志并提供出现卡顿前后的日志片段，重点关注 ActionEffect、Framework、时间轴和 DoT 相关慢包记录。
- 副本内停用部分时间轴重型自动同步后，个别依赖高频 Ability / StartsUsing 自动重同步的时间轴提示可能不如之前激进；这是本版为了避免绝本卡顿做出的保守取舍。
- 时间轴硬编码源码路径仅用于当前本地开发环境，不应随意修改。
- `IDutyState` 在当前 CN 环境下事件订阅会导致插件构造失败，本版本不接入 `DutyWiped`。
- 高性能模式会降低 DoT、野火、友方 NPC 和完整战斗流水的精确度；精确复盘时建议关闭。
- 四个悬浮模块的后台工作跟随对应显示开关；关闭窗口会停止对应模块的大部分采集/同步工作。
- `ActorControl` 事件当前用于战斗流水采集、MapEffect 同步和团灭淡出重置；头顶标记和连线尚不触发时间轴机制同步或 TTS。
- 队友监控和状态监控默认非战斗暂停刷新，窗口会显示最后一次缓存。
- 区域分类中的主城/住宅区使用内置 TerritoryId 表；如有遗漏区域，后续会继续补充。
- `duration` 当前用于时间轴数据字段和持续条语义说明；倒计时窗口是否完整展示持续过程以后续实现为准。
- 用户自放时间轴自动识别需要文件头包含 `# ZoneId: xxxx`；没有 ZoneId 的文件仍可通过强制加载测试。

## 验证建议

1. 确认 GitHub Release 页面标题为 `DalamudACT {{VERSION}}`。
2. 确认 Release 资产中包含 `DalamudACT.zip`。
3. 确认仓库 metadata / pluginmaster 中的下载链接指向本次 tag。
4. 在游戏中加载插件，确认主窗口显示版本与 `{{VERSION}}` 一致。
5. 在绝妖星或同等高压副本中确认帧率不再因插件掉到个位数。
6. 确认副本中 DPS / HPS / 承伤基础统计仍能正常刷新。
7. 确认时间轴窗口打开时不再明显拖慢帧率，并观察关键 TTS / 场地特效同步是否仍可用。
8. 确认队友技能监控倒计时、起效高亮和食物提示仍能正常显示。
9. 确认状态监控名称、图标、剩余时间和非战斗暂停提示仍能正常显示。
10. 回归确认高性能模式、轻量战斗流水、DoT/野火归属三个开关仍能保存并立即生效。
